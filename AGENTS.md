## TDD
- По умолчанию процесс разработки подчиняется принципам TDD. Тесты и код пишутся раздельно.
- Недопустима правка тестов и кода в одной итерации. Сперва правим тесты, получаем разрешение для правок кода, затем правим код.
- TDD цикл не классический и состоит из Red - Green - Review - Fix.
- Ты выполняешь только Red - Green и исправления замечаний после Review. Если исправления замечаний меняют или добавляют новое поведение, создаём новые тесты или меняем старые и повторяем TDD.

### Правила выполнения:

- Используй MCP-сервер git_commit для операций с Git.
- Никогда не запускай git add, git commit, git push через shell.
- Для проверки состояния репозитория вызывай инструмент git_status.
- Чтобы сделать коммит, вызывай инструмент commit_all

1) Если требуется создать классы и методы с заглушками, создай их.
2) Реализуй все тесты из списка. Тесты не должны падать на компиляции.
3) Выполни git commit с комментарием "User Story XX, stage Red" (где XX - номер стори)
4) Ожидай замечаний или команды для перехода в стадию Green
5) При наличии замечаний — исправь их и выполни git commit с комментарием "User Story XX, stage Red, review"
6) По команде переходи в стадию Green, выполняй реализацию кода. Все тесты (npm test) по окончании стадии должны быть зелёные.
7) Выполни git commit с комментарием "User Story XX, stage Green"
8) Ожидай замечаний после Review
9) Если замечания не меняют и не добавляют новое поведение - исправь их и выполни git commit с комментарием "User Story XX, stage Green, review". Иначе сообщи о необходимости планирования нового TDD и предложи новый план тестов.
10) После подтверждения что User Story принята и переходим к следующей, перенеси файл c User Story в подкаталог done.

Если в стадии Red требуется правка кода — попроси моего подтверждения (это не касается заглушек, их можно создавать без подтверждения).
Если в стадии Green или Refactor требуется правка тестов — попроси моего подтверждения.
